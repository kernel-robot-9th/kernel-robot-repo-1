## 1. 주문 처리 구조
```
주문 터미널 (ros2 run couping_integration order)
   │ /couping/order  {"id":"001","items":["carrot","bath_tissue"]}
   ▼
오케스트레이터 (대기열, 하나씩 처리)
   │ /couping/picker/cmd  "pick:carrot,bath_tissue"
   ▼
두산 피킹 노드 (doosan_picker)
   │ 품목마다: 관찰 자세에서 인식 → 수평으로 집기 → 박스에 넣기
   ▼
/couping/picker/status  running → progress:… → done / fail:<이유>
```
- 품목 번호: 1 토마토, 2 당근, 3 샐러드, 4 휴지(bath_tissue), 5 세제(tide), 6 키친타월(paper_towel)
- 입력: `1, 3` / `1 3` / `13` / `1,1`(같은 품목 2개)
- 명령: `s` 상태, `x` 정지(지금 품목까지만), `r` 재개, `q` 종료
- 실패하거나 정지하면 대기열이 멈추고 `r` 로 재개. 진열대에 없는 품목은 건너뛰고 나머지를 처리한 뒤 실패로 알림
- 핑키 주행·OMX 포장 단계는 launch 인자(`pinky:=true omx:=true`)로 켜면 피킹 뒤에 자동으로 이어짐

## 2. 한 품목 피킹 동작 (15단계)
1. 관찰 자세에서 인식 (팔을 위로 올려 진열대 12칸이 모두 보이는 자세)
2. front: 진열대 앞 수평 자세
3. 컵 정면 150mm 앞 → 그리퍼 50% 열기 → 20mm/s 로 수평 전진 → 잡기(힘 300)
4. 15mm 들어올리기 → 수평으로 빼기 → front
5. 박스 위로 관절 이동 (그리퍼가 아래를 향함) → 수직으로 내려가 그리퍼를 열어 떨어뜨림 → 위로 → 관찰 자세

움직이기 전에 모든 단계의 도달거리(200~850mm)·높이·방향을 먼저 검사하고, 하나라도 걸리면 출발하지 않는다. 오늘 카메라 깊이 값이 잘못 들어왔을 때(목표가 2m 뒤로 계산됨) 이 검사에 걸려 로봇이 움직이지 않았다.

## 3. 자세·보정 값
| 항목 | 값 | 방법 |
|---|---|---|
| 관찰 자세 (observe) | 관절 [-1.9, 10, 72.7, -2.5, 6.4, -0.3] | 직접교시, 12개 전부 인식 확인 |
| front | TCP (447, -70, 457) mm, 좌우 비틀림 1.5°, 아래 6.3° | 직접교시. 12칸 모두 계획 검사 통과 |
| 잡는 점 높이 | +33.5mm | 새 캘리브레이션에서 가운데 tide 에 그리퍼를 대고 비교 |
| 목표 보정 | 오른쪽(+X) 70mm, 아래 15mm | tide 앞에서 5~50mm 씩 움직여 가며 맞춤 |
| 전진 거리 | 컵 중심보다 7mm 더 | tide 시험 후 |
| 박스 자세 | 박스 위 +250mm 에서 아래로 돌림, +120mm 에서 놓음 | 박스 가운데를 한 번 재고 역기구학으로 계산 (하드코딩) |

박스는 위치가 고정이라 직접교시 대신 `couping/box_poses.py` 의 `BOX` 값으로 정했다. 위에서 떨어뜨리는 방식이라 여러 품목도 같은 자리에 넣는다. 박스를 옮기면 숫자만 고치고 `ros2 run couping box_poses` 를 다시 실행한다.

## 5. 하드웨어 문제와 대처
| 문제 | 증상 | 대처 |

## 7. 실행 순서
1. 두산 bringup → 그리퍼 서비스 (`ros2 run dsr_gripper gripper_service_a`)
2. `ros2 launch couping_integration integration.launch.py dsr_bringup:=false pinky:=false omx:=false vision:=true`
3. `ros2 run couping_integration order` → 번호 입력

한 품목만 단계별로 시험: `ros2 run couping auto_pick tomato --step`
