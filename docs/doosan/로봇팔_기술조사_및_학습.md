# 두산 로봇팔 기술조사 및 YOLO 학습 결과

## 1. 개요
- **담당**: 두산 로봇팔 (피킹)
- **목표**: 야채코너처럼 꾸민 진열대에서 주문 상품을 인식하고, 위치를 추정해 집을 수 있게 한다 (SR_05~SR_09)
- **장비**: 두산 E0509 + RH-P12-RN 그리퍼, Intel RealSense D455F (진열대 정면 고정 설치)
- **상품 6종**: 방울토마토(`tomato`), 당근(`carrot`), 샐러드(`salad`), 화장지(`bath_tissue`), 세제(`tide`), 키친타월(`paper_towel`)
  - 같은 모양의 투명 원통 컵 안에 상품 사진을 넣은 형태
  - 뚜껑 색은 상품 종류와 무관 (같은 상품에도 여러 색 뚜껑 사용)

## 2. 조사 결과 요약
| 조사 항목 | 결정 | 핵심 근거 |
|---|---|---|
| 진열대 배치 (세로 vs 비스듬히) | **현재 세로 진열대 유지** (경사 진열대는 선택사항) | 정면 고정 카메라에서 세로 배치로도 학습·인식이 잘 됨 |
| 물체 인식 방법 (YOLO vs 바코드) | **YOLO** | 거리 0.5m 이상, 방향 무관하게 인식, 바로 3D 좌표로 연결 가능 |
| 위치 추정 방법 | **YOLO 박스 + RealSense 깊이** (진열대 정보로 보정) | 실측 오차 1~2cm, 단 투명 부분은 깊이가 불안정 |
| 라벨링 범위 | **박스 + 클래스만** (위치·각도 라벨 없음) | 원통형이라 방향 무관, 접근 방향은 진열대 구조로 고정 |

## 3. 진열대 배치: 세로 vs 비스듬히
| | 세로로 세움 | 비스듬히 (15~30°) |
|---|---|---|
| 카메라에 보이는 면 | 정면 카메라 기준 앞면이 잘 보임 | 앞면이 카메라를 향해 잘 보임 |
| 칸끼리 가림 | 위·아래 칸이 일부 겹칠 수 있음 | 계단식이라 덜 가림 |
| 물건 위치 | 집어 가면 위치가 제각각 | 앞 턱(스토퍼)을 달면 항상 같은 자리로 미끄러져 옴 |
| 로봇 접근 | 정면에서 수평 접근 | 경사에 맞춰 그리퍼 각도 조정 필요 |

**결론**
- 처음에는 세로 배치에서 카메라 각도 때문에 학습이 어려울 것을 걱정했지만, 카메라를 **진열대 정면 약 0.5~0.6m에 고정**하니 세로 배치로도 학습과 인식이 잘 됐다 (5장 학습 결과 참고).
- YOLO는 진열대 각도보다 **"실제 카메라와 같은 각도에서 찍은 사진으로 학습했는지"**가 더 중요하다.
- 경사 진열대는 **물건 위치가 일정해진다**는 장점이 있어서, 집기가 불안정할 때 검토할 선택사항으로 남긴다.

## 4. 물체 인식 방법: YOLO vs 바코드
| | **YOLO (채택)** | 바코드/QR |
|---|---|---|
| 야채코너와 어울림 | 상품 모양 그대로 인식 (실제 매장과 비슷) | 상품에 라벨을 붙여야 함 |
| 인식 거리 | 0.5m 이상에서도 가능 | 바코드는 멀면 안 읽힘 (D455 해상도 기준 0.5m 이상은 작은 바코드 어려움) |
| 방향 | 어느 방향이든 인식 | 라벨이 카메라를 향해야 함 |
| 집을 위치 | 박스 중심 + 깊이 → 3D 좌표 | 라벨 위치라 물건 중심과 다를 수 있음 |
| 준비 | 사진 수집·라벨링·학습 | 라벨 제작·부착 |

**예비안**: YOLO 정확도가 부족하면, 진열대 **칸마다 ArUco 마커**를 붙여 칸 위치를 정확히 얻고 YOLO는 "칸에 어떤 물건이 있는지"만 판단하는 방식으로 전환한다.

## 5. 위치 추정: RealSense 깊이 측정 실험
**방법**: RGB 화면을 클릭하면 주변 7×7 픽셀 깊이의 중앙값으로 카메라 기준 3D 좌표(X, Y, Z mm)를 계산하는 도구를 만들어 측정했다. 깊이는 RGB에 정렬(align)했다.

**정확도 (자로 잰 거리와 비교)**
화면의 Z는 카메라 정면 방향 거리이고 자로 잰 값은 직선 거리라서, √(X²+Y²+Z²)로 바꿔 비교했다.

| 측정점 (가장 왼쪽 가운데 단 컵) | Z | 직선 거리 계산값 | 자로 잰 값 |
|---|---|---|---|
| #1 (유효 96%) | 502mm | 58.4cm | 약 60cm |
| #2 (유효 100%) | 502mm | 59.2cm | |
| #3 (유효 84%) | 517mm | 60.0cm | |

→ **오차 약 1~2cm**

**안정성 (찍는 위치별)**
| 위치 | 깊이 유효율 | 판단 |
|---|---|---|
| 가운데 단 | 84~100% | 안정적 |
| 맨 위 단 | 71~73% / 일부 0% | 사용 가능 ~ 불안정 |
| 맨 아래 단 | 55~100% / 일부 4% | 일부 값이 프레임마다 551 → 609mm로 튐 |

- **뚜껑·안의 종이(불투명)는 안정적**이고, **투명한 컵 몸통·가장자리는 깊이가 비거나 튄다.**
- D455는 약 0.4~0.5m 이상 떨어져야 깊이를 제대로 잰다. 카메라를 진열대 바로 앞에 두면 안 된다.

**결론: 깊이 + 진열대 정보를 함께 쓴다**
1. YOLO 박스 **안쪽 여러 점의 깊이 중앙값** 사용 (한 점만 쓰지 않음)
2. **유효율이 낮으면(예: 50% 미만) 버리고** 다시 측정
3. **높이는 가장 가까운 진열대 단 높이로 보정**
4. **앞뒤 거리는 진열대 앞면 범위로 제한**

→ 좌우 위치는 깊이로 정확히 얻고, 높이·앞뒤는 진열대 정보로 보정한다. 1~2cm 오차는 그리퍼 벌림 폭 안이라 집기에 문제없다.

**대안 (깊이가 부족할 때)**: 각 칸의 집기 자세를 **직접교시(수동 모드)로 미리 기록**하고, YOLO는 어느 칸에 무엇이 있는지만 판단한다. 깊이와 핸드-아이 캘리브레이션이 필요 없어 일정상 안정적이다.

## 6. 라벨링 범위: 박스만 vs 위치·각도까지
| 로봇에 필요한 정보 | 얻는 방법 | 라벨링 필요 |
|---|---|---|
| 무엇인지 (종류) | YOLO 클래스 | 필요 |
| 어디에 (3D 위치) | 박스 중심 + 깊이 → 카메라 좌표 → 핸드-아이 캘리브레이션 → 로봇 좌표 | 불필요 (사진 라벨로는 3D 위치를 알 수 없음) |
| 어떤 각도로 (접근 방향) | 진열대 구조로 고정: 정면에서 수평 접근 | 불필요 |

- 상품이 **원통형이라 돌려 놓아도 집는 방법이 같다** → 각도 정보가 의미 없음
- 칸 위에 칸이 있어 위에서 내려 집을 수 없으므로 **항상 정면 수평 접근** (접근점 → 전진 → 집기 → 후퇴)
- 각도·자세 라벨(YOLO-OBB, YOLO-pose)은 물건이 아무렇게나 눕혀져 있거나 특정 부위를 잡아야 할 때 필요하다. 현재 환경은 해당하지 않는다.

## 7. 데이터셋 구축
**촬영**
- 팀원이 만든 RealSense 촬영 스크립트(`create_data_capture.py`)를 수정해 사용: 재실행 시 덮어쓰기 방지, 저장 위치 고정, 화면에 장수 표시
- **15장** 촬영: 배치·뚜껑 색·칸 위치를 매번 섞음, 사람이 가린 사진·물건이 몰린 사진 포함

**라벨링 (Roboflow)**
- Roboflow **Auto Label**(AI 자동 박스)로 15장 라벨링 후 검토
- 결과: **박스 180개, 클래스당 30개, 사진당 12개**. 전수 확인 결과 클래스 오류 없음
- 클래스 설명에 뚜껑 색은 넣지 않음 (뚜껑 색은 종류와 무관)

**분할**
- 학습 12장 / 검증 3장 (`img_0003`, `img_0008`, `img_0013`)
- 검증은 **증강하지 않은 원본만** 사용 (점수가 실제보다 좋게 나오는 것 방지)

**증강 (학습 12장 → 252장)**
| 방법 | 내용 |
|---|---|
| 컵 바꿔치기 | 사진 속 컵의 약 40%를 다른 사진에서 잘라 온 **다른 종류의 실제 컵**으로 같은 자리에 교체 (가장자리 부드럽게 합성) → 상품 조합·위치 다양화 |
| 밝기·대비 | ±30% |
| 색조 | 아주 약하게 (당근·토마토 색 보존) |
| 흐림·노이즈 | 가끔 |
| 기하 변형 | 확대 0.9~1.15배, 이동 ±5%, 회전 ±3° |
| 좌우 뒤집기 | **사용 안 함** ("Tide", "Bath Tissue" 글자 반전 방지) |

- 검증 사진의 컵은 바꿔치기에 사용하지 않음 (정보 누출 방지)
- 결과: 학습 252장, 클래스별 박스 480~535개 (총 약 3,000개)

**사용하지 않은 데이터: `train.zip`**
- 원본 12장 × 17가지 변형(좌우·상하 뒤집기, 90/180/270° 회전, 대각 뒤집기, 확대·밝기 변형) = 204장
- **라벨(박스)이 없어서** 학습에 쓸 수 없음. 확대·밝기 변형은 변환 기록이 없어 라벨을 옮겨 붙일 수도 없음
- **뒤집기·90° 회전은 실제로 나올 일 없는 장면**(진열대가 눕거나 뒤집힘, 글자 반전)이라 오히려 성능을 떨어뜨릴 수 있음
- 같은 원본에서 만든 것이라 새로운 정보가 없음 → 위의 증강이 같은 역할을 더 현실적으로 수행
- 앞으로는 **증강보다 새 사진 촬영·라벨링**이 더 도움이 됨

## 8. YOLO 학습
**모델: YOLO11s (Ultralytics), COCO 사전학습 가중치에서 전이학습**
| 선택 | 이유 |
|---|---|
| YOLO11 | Ultralytics 최신 주력 모델, 사용법 간단, ROS 연동 예제 많음 |
| s 크기 (약 940만 파라미터) | 클래스 6개·데이터 250장 규모에 적합. n은 작은 컵을 놓칠 수 있고, m 이상은 데이터 대비 크고 느림 |
| 입력 해상도 1280 | 화면에서 컵이 60~80픽셀로 작음. 640으로 줄이면 30~40픽셀이 되어 컵 안 그림이 뭉개짐 |

**학습 설정**
- 최대 100 epoch, 배치 8, 조기 종료(30 epoch 동안 개선 없으면 중단)
- 학습 중 증강: 좌우·상하 뒤집기 끔, 회전 ±3°, 색조 변화 아주 약하게, 모자이크 사용
- 환경: RTX 5080 Laptop (16GB), PyTorch 2.14 (CUDA 13.0), Ultralytics 8.4, epoch당 약 20초

**결과 (검증 3장, 컵 36개 기준)**
- 77 epoch에서 조기 종료 (30 epoch 동안 개선 없음), **최고 성능은 47 epoch** (`best.pt`)
- 학습 시간 약 21분 (RTX 5080)

| 지표 | 값 | 의미 |
|---|---|---|
| Precision | 0.981 | 찾은 것 중 맞게 찾은 비율 |
| Recall | 0.998 | 실제 컵 중 찾아낸 비율 |
| mAP50 | 0.995 | 컵을 찾고 종류를 맞히는 정확도 |
| mAP50-95 | 0.960 | 박스를 얼마나 딱 맞게 치는지까지 본 엄격한 점수 |

**클래스별 결과**
| 클래스 | Precision | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| tomato | 0.972 | 1.000 | 0.995 | 0.932 |
| carrot | 0.971 | 1.000 | 0.995 | 0.962 |
| salad | 0.971 | 1.000 | 0.995 | 0.995 |
| bath_tissue | 0.971 | 1.000 | 0.995 | 0.973 |
| tide | 1.000 | 1.000 | 0.995 | 0.971 |
| paper_towel | 1.000 | 0.990 | 0.995 | 0.929 |

**검증 사진 추론 확인**: 검증 3장 모두 컵 12개를 전부 찾고 종류를 모두 맞힘 (신뢰도 0.79~0.96), 추론 속도 약 10ms/장

**주의**: 검증 사진이 3장뿐이고 학습 사진과 같은 환경에서 찍어서 점수가 후하게 나온다. 실제 성능은 **카메라 실시간 영상에서 배치·조명을 바꿔 가며** 확인해야 한다.

## 9. 다음 단계
1. **실시간 인식 확인**: RealSense 영상에 학습한 모델을 돌려 배치·조명을 바꿔 가며 확인
2. **추가 데이터**: 로봇 팔이 화면에 걸친 사진, 조명 변화, 컵이 돌아간 사진, 빈 칸이 많은 사진을 촬영·라벨링 후 재학습
3. **핸드-아이 캘리브레이션**: 카메라 좌표 → 로봇 좌표 변환 (카메라 고정이라 1회)
4. **집기 동작**: 정면 수평 접근 경로(접근점 → 전진 → 집기 → 후퇴), RH-P12-RN 집는 힘 설정
5. **ROS 2 노드화**: 인식 → 3D 좌표 → 두산 픽앤플레이스 → 오케스트레이터에 `done` 신호
